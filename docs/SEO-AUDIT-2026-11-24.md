## Live delivery, links and infrastructure

The read-only live crawl made **338 GET requests**: pages, referenced assets, discovery files, redirect/404 fixtures, 99 distinct external destinations and 30 crawler-agent requests. All **41 canonical live pages returned 200**, and **203 checks with local byte expectations matched** (41 HTML documents, 159 referenced resources and three discovery files). No files were uploaded.

Public canonical examples returned one 301 followed by 200. Compression returned `Content-Encoding: gzip` and `Vary: Accept-Encoding`. Fingerprinted CSS/images and content-addressed WOFF2 fonts retained `public, max-age=31536000, immutable`. The observed HTML response did not advertise an immutable lifetime. The tested missing path returned 404 rather than a homepage rewrite. The isolated Apache fixture passed 54 checks, including all 42 candidate pages, the new key file, redirects/query preservation and other-host isolation.

Canonical-page time to first byte from this connection ranged **0.536–0.708 seconds**, median **0.618 seconds**, during the crawl. These include the requesting connection and transport conditions; they are not measurements from Lebanon, Europe and North America separately. Public DNS at audit time returned www → apex and A `192.185.16.224`. Response headers identify Apache; they do not establish a global CDN. Enabling a CDN, changing caching or moving hosting without regional evidence is not justified by this audit.

Of 99 external destinations, 83 returned final 200 on the initial crawl. The Beirut Opera Festival HTTP/2 error resolved to 200 on HTTP/1.1 follow-up. **15 remain unresolved from automated access:** 13 return 403, LinkedIn returns 999, and the Expo virtual-event URL returns 520. These statuses do not establish that the links are broken for human visitors. Keep source/identity references until manually reviewed; especially check the Expo page and use another already-verified official reference if it is no longer available. No replacement credit or URL was invented.

Search sampling also surfaced `https://studiojpb.com/orchestra-sound-engineer/`. A fresh GET confirmed 200 with canonical `https://www.jeanpierreboutros.com/orchestra-sound-engineer/`. This separate domain shares the document root, as already documented. Canonical signals exist, but an alias appearing in a search sample is a reason to inspect Google's selected canonical. Do not apply a cross-domain redirect without deciding whether StudioJPB should retain its own site identity. That decision was outside the implementation on jeanpierreboutros.com.
